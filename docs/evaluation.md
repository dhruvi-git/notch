# Search evaluation

Generated by `SearchEvaluation` (api/src/test/java/dev/notch/api/eval). 50 labelled questions over 89 messages (89 passages) from a fictional startup's chats: `api/src/test/resources/eval/`.

Each chat goes through the real import steps (chunking, decision extraction, indexing) and the app's ranking code (`SearchPipeline`). Vector search uses the app's offline word-hashing embeddings, with an exact nearest-neighbour search in place of pgvector. A result counts for the message it came from.

## What the first run found

The evaluation was first run before any search changes. Its failures pointed to two bugs and one missing case. Each fix is a general mechanism with its own test (`QueryTermsCategoryTest`), not a weight tuned to these questions:

- **Expansions never matched stemmed words.** Query words are stemmed ("authentication" to "authentic", "hosting" to "host") but the expansion table was looked up with unstemmed keys, so most entries never matched. The table is now keyed by stem as well.
- **Words for a kind of tool didn't reach the tools.** "What did we decide about styling?" couldn't find "We chose CSS modules over Tailwind". Category words now expand to every tool Notch knows in that category, from the same catalogue the guard uses.
- **Time-only questions had no candidates.** "What did we work on yesterday?" matched no words. When nothing matches, the passages from the time window are now the candidates, ranked by recency.

| MRR@10 | First run | Now |
|---|---|---|
| Hybrid (what Notch does) | 0.719 | 0.794 |
| Exact only (suffix array) | 0.675 | 0.710 |
| Vector only (offline embeddings) | 0.345 | 0.345 |
| Hybrid, decision questions only | 0.533 | 0.833 |

Because the first run's failures guided the fixes, the current numbers are somewhat optimistic for these 50 questions. A fresh set written by someone else would be the fairer test.

## Limits of this evaluation

- The same person wrote the chats and the questions, which tends to favour word matching.
- The corpus is small (89 messages); real projects have thousands of passages, where ranking matters more.
- Vector search here is the offline word-hashing embedding, which shares words rather than meaning. With a real embedding model, paraphrased questions should do better; the harness takes any embedding client.
